## Docker Compose 是什么
![dockercompose](/api/get_img/Docker学习笔记(2)/1)

Docker Compose 是 Docker 提供的一个工具，用于定义和管理多容器应用。通过编写一个 `YAML` 格式的配置文件（通常命名为 docker-compose.yml），你可以描述应用所需要的多个服务，并通过一个命令来启动、停止和管理这些服务。

Docker Compose 允许你将应用的所有服务定义在一个文件中，无需单独管理每个容器。这对于复杂的多容器应用（例如前端、后端、数据库等多服务）尤其有用。

## Docker Compose的应用场景

#### 定义多个服务
通过一个配置文件 `docker-compose.yml`，你可以定义一个应用所需要的所有容器服务。例如，Web 前端、后端 API、数据库、缓存服务等都可以在同一个文件中进行描述和管理。

#### 自动化部署
只需要运行一个命令 `docker-compose up`，Docker Compose 会自动构建和启动多个容器，无需手动启动每个容器。

#### 服务依赖管理
Docker Compose 可以管理服务之间的依赖关系。你可以指定服务 A 依赖于服务 B，那么服务 A 在启动时，会等到服务 B 启动完成。

#### 网络配置
通过 Docker Compose，可以轻松定义服务之间的网络拓扑。它会自动为每个服务创建一个独立的网络，使容器之间能够通过服务名称进行通信，而无需关心具体的 IP 地址

#### 灵活的配置
Docker Compose 支持通过 `.env `文件或直接在 `docker-compose.yml` 文件中定义环境变量。环境变量可以用来配置应用的参数（例如数据库密码、API Key），以实现灵活的配置管理。

#### 不同环境的配置
通过不同的 Compose 文件或覆盖文件 `override files`，你可以为不同的环境（开发、测试、生产）指定不同的配置。

## 安装Docker Compose

在 MacOS/Windows 系统中，安装 Docker 客户端时会将 Docker Compose 作为插件一并安装；在 Linux/Ubuntu 系统中，通过 Docker 安装包也可以直接将 Docker Compose 作为 Docker CLI 的插件直接安装。所以，Docker Compose 在大多数时候不需要额外安装。如果在电脑中找不到 Docker Compose 服务，只需要检查 Docker 的安装情况即可。具体详见<a href="https://jutasite.top/blog/Docker学习笔记(1)"> Docker学习笔记(1)</a>。

## 使用Docker Compose
在实际生产环境的部署中，Docker Compose 经常用于前后端分离的应用。前端、后端、反向代理各需要一个容器来运行，因此需要使用 Docker Compose 来自动化部署这些容器。

本文将以静态网页为前端，`Python Flask` 为后端，`nginx` 为反向代理来介绍 Docker Compose 的使用。

### docker-compose.yml的构成
为了自动化部署各个容器，并组建容器网络，我们需要使用 `docker-compose.yml` 文件对 Docker Compose 进行设置。

`docker-compose.yml` 文件是 Docker Compose 用来定义和管理多容器应用的核心配置文件。它使用 `YAML` 格式，包含服务、网络、卷等定义，使你能够通过一个文件同时配置和管理多个 Docker 容器。

`docker-compose.yml` 主要由以下部分构成：
```text
docker-compose.yml
│
├── 服务（services）
│   ├── 服务的名称
│   ├── 镜像（image）
│   ├── 构建（build）
│   ├── 端口映射（ports）
│   ├── 环境变量（environment）
│   ├── 卷（volumes）
│   ├── 依赖（depends_on）
│   ├── 网络（networks）
│   └── 容器名称（container_name）
│    
├── 网络（networks）
├── 卷（volumes）
└── 其他选项
```


### 配置多容器 Dockerfile
首先建立大致如下的目录结构:
```text
project-root/
│
├── frontend/            # 静态网页前端目录
│   ├── index.html
│   └── Dockerfile
├── backend/             # Python Flask 后端目录
│   ├── app.py
│   ├── requirements.txt
│   └── Dockerfile
├── nginx/               # Nginx 配置目录
│   └── default.conf
└── docker-compose.yml   # Docker Compose 配置文件
```
本文重点讲解 Docker，`index.html`，`app.py`和 `default.conf` 本文在这里提供简单示例:
```html
<!-- frontend/index.html -->
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>静态前端</title>
</head>
<body>
    <h1>Hello from the Static Frontend!</h1>
</body>
</html>
```
```python
# backend/app.py
from flask import Flask, jsonify

app = Flask(__name__)

@app.route('/api')
def hello_api():
    return jsonify(message="Hello from Flask API!")

if __name__ == '__main__':
    app.run(host='0.0.0.0', port=5000)
```
```nginx
# nginx/default.conf
server {
    listen 80;

    # 前端静态页面
    location / {
        proxy_pass http://frontend:80;  # 将请求转发到前端静态网页服务
    }

    # 后端 API 服务
    location /api {
        proxy_pass http://backend:5000;  # 将 /api 的请求转发到 Flask 后端服务
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

接下来，我们分别构建前端和后端的 Dockerfile。由于 nginx 使用的是 Docker Hub 的公共镜像，所以不需要自己使用 Dockerfile 创建镜像。

### 建立前端 Dockerfile

为了将静态网页交付给 nginx 服务器进行托管，我们要以 nginx 为基础镜像进行构建，将 `index.html` 复制到 nginx 的托管目录下。
```dockerfile
FROM nginx:alpine
# 以 nginx 为基础镜像

COPY ./index.html /usr/share/nginx/html/index.html
# 使用 COPY 将 index.html 复制到 nginx 的托管目录

EXPOSE 80
# 暴露 80 端口
```
这样，前端的镜像就构造完毕了。

### 建立后端 Dockerfile
由于后端使用的是 Python，我们首先要基于 Docker Hub 的 Python 镜像来构建。
```dockerfile
FROM python:3.9
```
接着，我们需要设置工作目录，一般设为 `/app`。
```dockerfile
WORKDIR /app
```
其次，我们需要安装需要的依赖。这个示例中我们使用的是 Flask，所以要在 `requirements.txt` 中添加 `Flask==2.0.3`。
```dockerfile
COPY requirements.txt .
# 将 requirements.txt 复制到工作目录

RUN pip install requirements.txt
# 安装依赖
```
然后，我们要把 `app.py` 等后端脚本复制到工作目录。
```dockerfile
COPY . .
```
最后，我们需要指定端口和运行指令。
```dockerfile
EXPOSE 5000
CMD ["python", "app.py"]
```
你会注意到，我在安装依赖之后才复制项目文件。那么我们为什么不首先 `COPY . .` 然后再安装依赖，这样镜像不会少一层吗？然而虽然镜像少了一层，却会带来构建速度缓慢的负面效果。将安装依赖和复制项目文件合为一层之后，如果项目文件(例如 `app.py`)发生了改动，那么这一层就需要重新构建，也就是需要重新安装依赖，而依赖往往是不需要重新安装的，除非 `requirements.txt` 发生改动。

### 构建 docker-compose.yml
首先定义一个网络，供容器间通讯使用。
```yaml
networks:
  app-network:        # 网络名称是"app-network"
    driver: bridge    # 使用 bridge 驱动创建网络（适用于容器间通讯）
```
接下来定义服务。
#### 前后端服务
```yaml
services:
  frontend:
    build:
      context: ./frontend
    container_name: frontend
    expose:
      - 80  # 只在容器间通信暴露端口
    networks:
      - app-network

  backend:
    build:
      context: ./backend
    container_name: backend
    expose:
      - 5000
    networks:
      - app-network
```
在这个示例中，因为前后端服务都很简单，所以并不需要用到 `services` 的所有配置项。以后端的服务配置为例分析这个简单的`services`配置：
```yaml
backend:                    # 定义服务名称
  build:                  
     context: ./backend     # 指定内容目录，Docker Compose会在这个目录下寻找 Dockerfile
  container_name: backend   # 定义容器名称
  expose:                   # 指定暴露端口
    - 5000
  networks:                 # 指定所使用的网络
    - app-network
```
#### nginx 服务

```yaml
  nginx:
    image: nginx:alpine
    container_name: nginx
    ports:
      - "80:80"  # 暴露到主机的 80 端口
    volumes:
      - ./nginx/default.conf:/etc/nginx/conf.d/default.conf  # 挂载 Nginx 配置
    depends_on:
      - frontend
      - backend
    networks:
      - app-network
```
nginx 的服务配置和前后端的服务配置其实相差并不多，但使用了 `volumes` 和 `depends_on`。
```yaml
volumes:
  - ./nginx/default.conf:/etc/nginx/conf.d/default.conf
```
这条卷挂载配置将主机上的 `./nginx/default.conf` 文件挂载到容器内部的 `/etc/nginx/conf.d/default.conf` 位置。具体分为以下几个部分：
```text
./nginx/default.conf：这是主机上的文件路径，指定了本地文件的相对路径。./ 表示的是当前 docker-compose.yml 文件所在的目录，所以它会在当前目录下的 nginx 文件夹中寻找 default.conf 文件。
本地路径可以是绝对路径 /path/to/file，也可以是相对路径 ./path/to/file。
这里 ./nginx/default.conf 表示在主机的当前目录下有一个名为 default.conf 的 Nginx 配置文件。
```
```text
/etc/nginx/conf.d/default.conf：这是容器内部的文件路径。在这里，Nginx 会默认查找其配置文件，因此我们将主机上的配置文件挂载到这个位置，覆盖容器中原有的 Nginx 配置文件。
容器内部的路径是绝对路径，表示挂载的文件或目录在容器中的位置。在这个例子中，/etc/nginx/conf.d/default.conf 是 Nginx 默认的配置文件位置。
```
因此，卷挂载的格式通常是：
```text
volumes:
  - 主机路径:容器路径
```
至此，完整的 `docker-compose.yml` 就完成部署了。这是 Docker Compose 较为基础的用法，完整示例如下：
```yaml
services:
  frontend:
    build:
      context: ./frontend
    container_name: frontend
    expose:
      - 80  # 只在容器间通信暴露端口
    networks:
      - app-network

  backend:
    build:
      context: ./backend
    container_name: backend
    expose:
      - 5000
    networks:
      - app-network

  nginx:
    image: nginx:alpine
    container_name: nginx
    ports:
      - "80:80"  # 暴露到主机的 80 端口
    volumes:
      - ./nginx/default.conf:/etc/nginx/conf.d/default.conf  # 挂载 Nginx 配置
    depends_on:
      - frontend
      - backend
    networks:
      - app-network
      
  networks:
  app-network:
    driver: bridge
```

## 分环境部署容器
一般来说，开发环境并不适用投入生产，会带来性能下降、安全隐患等问题。于是，我们就需要分开开发环境和生产环境。这就需要两套 Docker 文件，即一份 `Dockerfilr.dev`， 一份 `Dockerfile.prod`。相对应的，还有 `docker-compose.dev.yml` 和 `docker-compose.prod.yml`。

于是，分开环境的项目目录内容大致如下：
```text
project-root/
│
├── frontend/            # 静态网页前端目录
│   ├── index.html
│   ├── Dockerfile.prod
│   └── Dockerfile.dev
├── backend/             # Python Flask 后端目录
│   ├── app.py
│   ├── requirements.txt
│   ├── Dockerfile.prod
│   └── Dockerfile.dev
├── nginx/               # Nginx 配置目录
│   └── default.conf
├── docker-compose.dev.yml
└── docker-compose.prod.yml   # Docker Compose 配置文件
```
配置时，只需要注意将 `docker-compose.yml` 中的 `Dockerfile` 换成对应环境的 `Dockerfile` 即可。在不同环境中启动容器时，只需要指定 `docker-compose.yml` 文件即可。
```bash
sudo docker-compose -f docker-compose.dev.yml up
sudo docker-compose -f docker-compose.prod.yml up
```
