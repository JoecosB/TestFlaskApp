# Docker学习笔记(1)

## 为什么要学习Docker?
![img](/api/get_img/Docker学习笔记(1)/1)

Docker 的作用就是将服务封装成独立环境的、轻量级的`容器`。不同的容器之间是相互独立的，无论是消耗的计算机资源还是环境都不会互相干扰。因此无论是在开发环境还是生产环境，Docker 都可以轻松的部署、调试你的服务项目。

与此同时，Docker 还可以进行跨平台的兼容。只要你的运行环境支持 Docker，你在任何时间、任何地点创建过的 Docker 容器都能在这个环境中正常部署。总体来说，Docker 简化了应用程序的开发、测试和部署过程，提高了软件交付的速度和质量。

## 如何安装并启动Docker服务

### MacOS/Windows
在 MacOS，Windows 环境中，我个人都建议安装 Docker 桌面版。Docker 桌面版提供了一个简洁、多功能的UI，可以轻松的访问容器内部，检查容器的运行情况、文件等，提供了方便的debug途径。可以访问<a href="https://www.w3schools.com"> Docker Downloads </a>来安装。

安装完毕之后，只需要打开桌面端App即可启动 Docker 服务。将桌面UI关闭并不会关闭 Docker 服务，Docker 服务将会在后台继续运行。

### Ubuntu/Linux
在 Ubuntu/Linux 中，可以使用命令行来安装。Docker 有官方的安装脚本，建议使用安装脚本安装。
```bash
curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh get-docker.sh
```
安装完毕之后，检查安装情况。
```bash
docker --version
```
按理来说，安装完毕之后 Docker 服务会自行启动。为了确保 Docker 的启动，我们再可以手动启动一次，并设置开机启动。
```bash
sudo systemctl start docker
sudo systemctl enable docker
```

## 镜像、容器、卷

### 镜像(Image)
Docker 镜像是一个只读的模板，其中包含了运行应用程序所需的所有内容。它包括了文件系统、依赖库、环境变量、配置文件、以及可执行的二进制文件（例如，一个应用程序的代码）。镜像可以被看作是一个应用程序的“快照”。

特点:
```text
只读：镜像是不可修改的。每次运行容器时，Docker 都会基于该镜像创建一个可写的层，这样原始镜像的内容不会被改变。
分层结构：镜像是由多个层组成的，每个层代表了镜像的一部分修改。通过分层结构，Docker 能够有效地利用存储资源，因为相同的层可以在多个镜像之间共享。
可复用：镜像可以在不同的环境中复用。无论是在开发环境、测试环境，还是在生产环境中，镜像的行为都是一致的。
```
### 容器(Container)
Docker 容器是镜像的运行实例。容器是一个独立的、可执行的环境，它在其中运行应用程序。容器可以看作是镜像的一个动态实例，它包含了镜像的所有内容，并且在其上增加了一个可写层。

特点:
```text
轻量级：容器共享主机操作系统的内核，因此比虚拟机更轻量，启动速度更快，占用的资源更少。
可写层：容器的可写层允许在运行时对文件系统进行更改。容器停止或删除时，这些更改可以被丢弃，或者通过提交容器生成一个新的镜像来保存这些更改。
隔离性：容器之间是相互隔离的，确保了应用程序之间的环境独立性。每个容器都有独立的文件系统、进程空间和网络接口。
```

### 卷(Volume)
卷是由 Docker 管理的文件系统中的目录，用于保存和共享数据。卷的生命周期独立于容器，卷可以存储在主机文件系统中的特定位置，并且可以在多个容器之间共享。

特点：
```text
持久性：卷的数据即使容器删除或重新启动，仍然存在。这使得卷非常适合存储需要持久化的数据，例如数据库、日志文件、配置文件等。
独立性：卷独立于容器的生命周期，可以在不同的容器之间共享使用。这意味着多个容器可以读写同一个卷中的数据。
自动化管理：Docker 会自动管理卷的挂载点、路径和权限。用户可以通过 Docker 命令创建、挂载和管理卷。
可移动性：卷可以在不同的主机间复制或移动，使得数据的备份和迁移更加容易。
```

### 三者之间的关系
镜像是通过 Dockerfile 创建的只读模版，使用 Docker 运行容器时并不会修改镜像的内容。当容器启动时，Docker 会加载镜像的只读层，并在其上创建一个可写层。所有容器中的文件改动都发生在这个可写层中。卷则是一种持久化数据的机制，用于保存容器运行中生成的数据，并可以在多个容器之间共享。卷是独立于容器的。当停止 Docker 容器的运行之后，卷并不会消失，因此可以用卷来储存永久性数据，例如用户数据、系统日志等。

## 试着部署容器
这里用 bash 命令行为示例，部署一个 nginx 服务器。

### 选择并下载基础镜像
Docker Hub 是一个提供各种官方和社区维护镜像的公共仓库。你可以使用 `docker pull` 命令来下载镜像。
```bash
sudo docker pull nginx
```

### 运行容器
下载镜像后，你可以使用 `docker run` 命令来启动一个容器。
```bash
sudo docker run --name test-nginx -d -p 8080:80 nginx
# --name my-nginx 为容器指定名称。  
# -d 使容器在后台运行（即“分离模式”）(detached)。  
# -p 8080:80 将主机的 8080 端口映射到容器的 80 端口(port)。  
# nginx 是你要运行的镜像名称。  
```
此命令运行后，nginx 服务会在容器中启动，你可以通过访问 http://localhost:8080 在浏览器中查看运行的 nginx 服务器。

### 进入容器并更改
如果使用的是桌面版，那只需要从 Docker 的桌面端UI进入容器即可。在 Ubuntu/Linux 上，还可以通过命令行进入容器。
```bash
docker ps
```
这个命令会列出电脑上运行的所有 Docker 容器，使用 `docker exec` 进入容器的命令行。
```bash
docker exec -it test-nginx /bin/sh
# -it 使得你能够以交互模式进入容器。
# test-nginx 是容器名称。
# /bin/sh 是你要在容器中运行的命令，这里是运行命令行。
```

### 保存更改后的镜像
在容器中进行更改之后，可以通过 docker commit 来创建新的镜像保存修改。
```bash
docker commit test-nginx test-nginx-v2
```
这会创建一个新的镜像 `test-nginx-v2` ，下一次可以直接基于这个新的镜像启动 Docker 容器。

## 通过Dockerfile创建镜像
通常情况下，在开发过程中我们需要自己创建镜像以满足开发需求。这时，我们就需要利用 Dockerfile 来进行镜像的配置。这里还是使用简单的静态网页和 nginx 服务器为示例。

### 创建配置文件
首先在工作目录下创建一个 `index.html`
```html
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>My Simple Web Page</title>
    <style>
        body {
            font-family: Arial, sans-serif;
            text-align: center;
            padding: 50px;
        }
        h1 {
            color: #333;
        }
    </style>
</head>
<body>
    <h1>这是一个一个一个测试网页!</h1>
    <p>This is a simple static page deployed with Docker and Nginx.</p>
</body>
</html>
```
然后在工作目录下创建一个 Dockerfile
```dockerfile
# 使用官方的 Nginx 基础镜像
FROM nginx:latest

# 将静态网页文件复制到 Nginx 默认的根目录
COPY index.html /usr/share/nginx/html/index.html

# 暴露 80 端口
EXPOSE 80

# 启动 Nginx 服务
CMD ["nginx", "-g", "daemon off;"]
```

### 构建镜像并启动容器
确保你的命令行在 Dockerfile 的工作目录中，使用 `docker build` 来构建镜像
```bash
docker build -t test-webpage .
# -t ：指定镜像的名称为 test-webpage。
#  . ：表示 Dockerfile 位于当前目录。
```
镜像构建完毕之后，就可以启动容器了。
```bash
docker run -d -p 8080:80 --name test-webpage-container test-webpage
```
现在，你可以在浏览器中访问 http://localhost:8080，查看运行在 Docker 容器中的静态网页。

## Dockerfile的工作原理

### 镜像的分层结构
Docker 镜像是分层构建的，每一条 Dockerfile 指令都会创建一个新的镜像层。这些层是只读的，并且可以在多个镜像之间共享。例如，如果你有两个镜像，它们都基于相同的基础层，那么这个基础层只会存储一次，从而节省存储空间。

层的类型:
```text
基础层：通常由 FROM 指令指定，定义了镜像的基础，例如 FROM ubuntu:20.04。
中间层：由每个后续指令创建，例如 RUN apt-get update 会在基础层之上创建一个新的层。
最终层：由最后一条指令生成，包含了最终的应用程序环境。
```

### 执行指令
Dockerfile 中的指令是按顺序执行的。每个指令都会创建一个新的镜像层并缓存结果。如果 Docker 在构建镜像时发现某一层已经构建过，并且没有变化，它会直接使用缓存而不是重新执行指令，从而加速构建过程。


常见的 Dockerfile 指令包括：
```text
FROM：
指定基础镜像。每个 Dockerfile 必须以 FROM 开始。例如，FROM nginx:latest 使用最新的 Nginx 官方镜像作为基础。

RUN：
执行命令并创建镜像层。通常用于安装软件包或修改镜像内容。例如，RUN apt-get update && apt-get install -y curl。

COPY 和 ADD：
将文件或目录从构建上下文复制到镜像中。COPY 是直接复制，ADD 则支持更多功能（如解压 tar 文件）。例如，COPY index.html /usr/share/nginx/html/。

CMD：
指定容器启动时要执行的命令。这条命令在容器启动时运行。例如，CMD ["nginx", "-g", "daemon off;"]。如果有多个 CMD，只有最后一个生效。

ENTRYPOINT：
类似于 CMD，但用来指定容器启动时要运行的主进程，并且不能轻易被覆盖。ENTRYPOINT 和 CMD 可以结合使用。

WORKDIR：
设置接下来执行命令的工作目录。例如，WORKDIR /app 之后的所有命令都会在 /app 目录下执行。

ENV：
设置环境变量。例如，ENV PATH /usr/local/nginx/bin:$PATH。

EXPOSE：
声明容器在运行时监听的端口。例如，EXPOSE 80。这只是一个声明，并不会自动进行端口映射。

VOLUME：
创建一个挂载点以便持久化存储。例如，VOLUME /data。

USER：
指定接下来执行命令的用户。例如，USER nginx 让后续命令以 nginx 用户身份运行。

ARG：
定义构建时的参数，可以在 docker build 时通过 --build-arg 传递。例如，ARG VERSION=1.0。

LABEL：
添加元数据，例如维护者信息或版本信息。例如，LABEL maintainer="yourname@example.com"。
```

### 入口点和命令

CMD 和 ENTRYPOINT 是 Dockerfile 中用于定义容器启动时执行的命令的两种指令。它们的区别在于：
```text
CMD：
定义默认执行的命令或参数。可以在 docker run 时被覆盖。

ENTRYPOINT：
定义一个固定的执行命令，通常用于将容器配置为一个特定的应用程序的“入口点”。即使用户在 docker run 时提供了命令行参数，这些参数也会传递给 ENTRYPOINT 指定的命令。
```
例如，以下 Dockerfile 设置了 ENTRYPOINT 和 CMD 的组合：
```Dockerfile
ENTRYPOINT ["nginx"]
CMD ["-g", "daemon off;"]
```
这里先设定入口点为 `nginx`，于是之后CMD传入的 `-g` 和 `daemon off` 都成为了入口点的参数。这样一来，完整的传入命令就成为了 `nginx -d daemon off`。如果你提供了其他参数，例如 `docker run <image> -v`, 这些参数会替代 CMD 指定的默认参数，但 nginx 仍然会是入口点命令。

## 镜像的分层构建过程

### 层的定义
层是镜像构建过程中生成的一组文件或变更。每条 Dockerfile 指令（如 FROM、RUN、COPY 等）都会创建一个新的层。这些层是按顺序堆叠起来的，每一层在前一层的基础上添加新的内容。

例如，假设有以下 Dockerfile：
```dockerfile
FROM ubuntu:20.04
#第1层：FROM ubuntu:20.04 这是基础层，基于官方的 ubuntu:20.04 镜像。这个镜像本身由若干层构成。

RUN apt-get update && apt-get install -y nginx
#第2层：RUN apt-get update && apt-get install -y nginx 这条指令会在上一层的基础上安装 Nginx，并生成一个新的层。

COPY index.html /usr/share/nginx/html/index.html
#第3层：COPY index.html /usr/share/nginx/html/index.html 这条指令将 index.html 文件复制到镜像中，并创建另一个层。
```
层的特点:
```text
只读性：每个镜像层都是不可变的、只读的。层的不可变性意味着一旦创建，层的内容不能修改。这有助于镜像的稳定性和一致性。
共享性：相同的层可以在不同的镜像之间共享。例如，如果两个镜像都基于同样的基础镜像（如 ubuntu:20.04），那么这个基础层只会存储一次，不同的镜像可以共享它。这种共享减少了存储需求并加快了构建和部署速度。
分层构建：Docker 使用分层文件系统来管理和组织镜像。每一层只包含相对于前一层的差异。这种机制使得 Docker 可以高效地管理镜像，并且支持镜像层的复用。
缓存机制：当 Docker 构建镜像时，它会缓存每一层的构建结果。如果重新构建相同的镜像，而前面的层没有变化，Docker 就会复用缓存层，而不会重新执行指令，从而加快构建过程。
```

### 层的优化
由于每一条 RUN、COPY、ADD 等指令都会创建一个新的层，优化 Docker 镜像的一个重要方法是减少层的数量。例如，可以通过将多个命令合并成一个 RUN 指令来减少层的数量：
```dockerfile
# 分成多个层
RUN apt-get update
RUN apt-get install -y curl nginx
RUN apt-get clean && rm -rf /var/lib/apt/lists/*

# 合并成一个层
RUN apt-get update && apt-get install -y curl nginx && apt-get clean && rm -rf /var/lib/apt/lists/*
```

### 多阶段构建镜像
在一个 Dockerfile 中，可以有多个 `FROM` 指令，每个 `FROM` 指令会标志着一个新的构建阶段的开始。这种功能称为 多阶段构建（multi-stage build），它在优化镜像大小和构建效率方面非常有用。

每个 FROM 指令都会开始一个新的构建阶段，并且每个阶段的基础镜像是独立的。每个阶段的文件系统与其他阶段隔离。 尽管每个阶段是独立的，你可以在后续的阶段中通过 `COPY --from=<stage>` 指令从前一个阶段中复制文件。这使得你可以只将构建产物（如编译后的二进制文件）带入最终的镜像，而无需包含整个构建环境（如编译器和开发工具）

假设你有一个简单的 Go 应用程序，你希望使用多阶段构建来编译这个应用，并创建一个只包含编译后二进制文件的精简镜像。
```dockerfile
# 第一阶段：构建阶段，使用AS将阶段命名为builder
FROM golang:1.20 AS builder

# 设置工作目录
WORKDIR /app

# 复制源代码并编译
COPY . .
RUN go build -o myapp

# 第二阶段：创建精简的运行时镜像
FROM alpine:latest

# 将编译后的二进制文件从构建阶段复制过来
COPY --from=builder /app/myapp /usr/local/bin/myapp

# 设置容器启动时的命令
CMD ["myapp"]
```
分析这个 Dockerfile

```text
第一阶段 (builder)：
    基于 golang:1.20 镜像，这个镜像包含了构建 Go 应用所需的所有工具和依赖。
    工作目录设置为 /app，然后将整个应用代码复制到该目录。
    使用 go build 命令编译应用程序，生成的二进制文件命名为 myapp。
    这个阶段的镜像包含了整个 Go 构建环境，但这些内容在最终的运行镜像中不需要。
第二阶段：
    基于 alpine:latest 镜像，这是一个非常小的基础镜像（只有几 MB），适合用作最终的运行时环境。
    使用 COPY --from=builder 指令，将第一阶段（即 builder 阶段）中生成的 myapp 二进制文件复制到 alpine 镜像的 /usr/local/bin/ 目录中。
    置容器启动时执行的命令为 myapp。
```
通过这种方式构建的镜像是基于 `alpine` 的，并且只包含 builder 阶段产生的二进制文件 `myapp` ，因此非常轻量化，可以快速部署，非常适合用于生产环境。
